# Publishing the sanitized release

This directory is the public release candidate. The original project folders
are archives and must not be copied to GitHub.

## 1. Revoke exposed credentials first

A cleanup commit does not make an exposed credential safe. Before pushing:

1. Revoke and recreate the old Hugging Face access token.
2. Revoke and recreate the old Gemini/Google API key.
3. Delete or disable exposed Firebase Admin service-account keys.
4. Remove the exposed SSH public keys from every server's
   `authorized_keys` file, then generate a new key pair if cluster access is
   still needed.
5. Rotate any Google or Microsoft OAuth client secret that appeared in a
   local environment file or shared archive.

Do not copy the new values into source files. Keep them in local environment
files, runtime mounts, or a secret manager.

## 2. Decide what to do about old Git history

The archived fork snapshot inspected for this release contained live-looking
credentials. If those values were ever pushed, adding this sanitized tree in
a new commit does not remove them from old commits, forks, pull requests, or
caches.

The simplest and safest portfolio publication is a new standalone repository
created from this directory with one clean initial commit.

If you must retain the existing fork, follow GitHub's sensitive-data removal
procedure using `git-filter-repo`, coordinate with every collaborator,
force-push the rewritten refs, and contact GitHub Support when the guide
requires it:

<https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository>

Always rotate the credentials before rewriting history.

## 3. Recommended: publish a new clean repository

Create an **empty** repository on GitHub without an autogenerated README,
license, or `.gitignore`. Then replace the placeholders and run:

~~~powershell
$RepositoryUrl = "https://github.com/YOUR-USERNAME/kumeet.ai.git"
$Source = (Resolve-Path "D:\Masaüstü\Spring25\COMP491\kumeet.ai-public").Path

Set-Location -LiteralPath $Source
if (Test-Path -LiteralPath ".git") {
    throw "This release directory already has Git history; stop and inspect it."
}

powershell -NoProfile -ExecutionPolicy Bypass `
    -File ".\scripts\check-public-release.ps1" -Path "."
if ($LASTEXITCODE -ne 0) {
    throw "Public-release check failed"
}

git init -b main
git config user.name "YOUR NAME"
git config user.email "ID+USERNAME@users.noreply.github.com"

git add -A
git diff --cached --check -- README.md PUBLISHING.md SECURITY.md .gitattributes scripts docs
git diff --cached --stat
git status --short
git commit -m "Publish sanitized KuMeet.ai release"

git remote add origin $RepositoryUrl
git push -u origin main
~~~

The GitHub-provided noreply address is available under **Settings → Emails**.
Verify the staged file list before committing.

## 4. Update the existing fork from a fresh clone

This procedure replaces the fork's current tree, but **does not scrub its old
history**. Use it only after making the history decision in section 2.

Use a fresh staging clone so the archived source folders cannot be included by
accident. Replace the placeholders below.

~~~powershell
$ForkUrl = "https://github.com/YOUR-USERNAME/YOUR-FORK.git"
$Source = (Resolve-Path "D:\Masaüstü\Spring25\COMP491\kumeet.ai-public").Path
$Stage = "D:\Masaüstü\Spring25\COMP491\kumeet-publish-staging"

if (Test-Path -LiteralPath $Stage) {
    throw "The staging path already exists: $Stage"
}

git clone $ForkUrl $Stage
Set-Location -LiteralPath $Stage

git config user.name "YOUR NAME"
git config user.email "ID+USERNAME@users.noreply.github.com"

$DefaultBranch = (git symbolic-ref --short refs/remotes/origin/HEAD) -replace "^origin/", ""
git switch $DefaultBranch
git pull --ff-only origin $DefaultBranch

git switch -c release/public-sanitized
git rm -r -- .

robocopy $Source $Stage /E /XD .git
if ($LASTEXITCODE -gt 7) {
    throw "robocopy failed with exit code $LASTEXITCODE"
}

powershell -NoProfile -ExecutionPolicy Bypass `
    -File "$Stage\scripts\check-public-release.ps1" -Path $Stage
if ($LASTEXITCODE -ne 0) {
    throw "Public-release check failed"
}

git add -A
git diff --cached --check -- README.md PUBLISHING.md SECURITY.md .gitattributes scripts docs
git diff --cached --stat
git diff --cached --name-status
git status --short
git commit -m "Prepare sanitized public release"
git push -u origin release/public-sanitized
~~~

On GitHub, open a pull request from `release/public-sanitized` into the
default branch of your fork. Merge it only after reviewing the complete file
list. Do not bypass a GitHub push-protection warning:

<https://docs.github.com/en/code-security/concepts/secret-security/push-protection>

## 5. Configure the fork relationship

The cloned fork uses `origin` for your repository. If you also need to fetch
changes from the original project:

~~~powershell
git remote add upstream https://github.com/ORIGINAL-OWNER/ORIGINAL-REPOSITORY.git
git remote -v
~~~

GitHub's fork-remote guide:

<https://docs.github.com/en/pull-requests/how-tos/work-with-forks/configuring-a-remote-repository-for-a-fork>

## 6. Keep your commit email private

This machine has a personal university email configured globally. The
repository-local `git config` commands above override it for these commits.
Confirm before committing:

~~~powershell
git config --get user.name
git config --get user.email
~~~

GitHub's commit-email guide:

<https://docs.github.com/en/account-and-profile/how-tos/email-preferences/setting-your-commit-email-address>
